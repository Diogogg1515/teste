┌─────────────────────────────────────────────────────────────────────────────┐
│ COMANDOS MANUAIS NECESSÁRIOS                                                │
└─────────────────────────────────────────────────────────────────────────────┘

Execute estes comandos ANTES de testar o sistema:

1. INSTALAR BIBLIOTECA PDF

   cd C:\Users\User\souza.l
   npm install @react-pdf/renderer


2. INSTALAR PLAYWRIGHT

   cd tests
   npm install
   npx playwright install
   cd ..


3. APLICAR MIGRATION RETENÇÃO

   npx supabase db push


4. DEPLOY EDGE FUNCTION

   npx supabase functions deploy cleanup-services


5. CONFIGURAR CRON NO SUPABASE DASHBOARD

   a) Acesse: https://supabase.com/dashboard
   b) Selecione seu projeto
   c) Vá em: Edge Functions → cleanup-services
   d) Clique em "Add Cron Job"
   e) Schedule: 0 3 * * *
   f) Salve


6. ATUALIZAR DADOS TRABALHADOR

   Edite: lib/worker-info.ts

   Troque:
     name: "Seu Nome Real"
     phone: "5511999999999"  // WhatsApp sem espaços nem +

   (Os outros campos também podem ser ajustados: profissão, região,
   serviços, portfólio)


┌─────────────────────────────────────────────────────────────────────────────┐
│ COMO TESTAR LOCALMENTE                                                      │
└─────────────────────────────────────────────────────────────────────────────┘

1. INICIAR DEV SERVER

   npm run dev


2. CRIAR CONTA CLIENTE

   a) Acesse: http://localhost:3000
   b) Clique "Entrar" → "Cadastre-se"
   c) Preencha: nome, e-mail, senha
   d) Após cadastro, copie o CÓDIGO DO CLIENTE (6 caracteres)


3. CRIAR CONTA TRABALHADOR (via Supabase Dashboard)

   a) Supabase Dashboard → Authentication → Users → Add User
   b) E-mail: worker@souza.local
   c) Senha: senha123
   d) Confirme

   e) Vá em: Table Editor → profiles
   f) Encontre o usuário recém-criado
   g) Edite: role = "worker"
   h) Salve


4. FLUXO COMPLETO

   PASSO 1 — Trabalhador cria pedido:
     • Login: worker@souza.local / senha123
     • Clique "Novo Serviço"
     • Cole o código do cliente
     • Descreva o serviço
     • Envie

   PASSO 2 — Cliente aceita:
     • Login com conta cliente
     • Veja "Pedidos Pendentes"
     • Clique no pedido
     • Digite endereço do serviço
     • Aceite

   PASSO 3 — Ambos adicionam registros:
     • Na página do serviço
     • Cliente: como ficou, fotos
     • Trabalhador: problema, causa, serviço realizado, materiais
     • Upload fotos (opcional)

   PASSO 4 — Trabalhador conclui:
     • Expanda "Marcar como Concluído"
     • Confirme

   PASSO 5 — Cliente solicita laudo:
     • Clique "Solicitar Laudo"

   PASSO 6 — Trabalhador gera:
     • Clique "Gerar Laudo"
     • Aguarde processamento

   PASSO 7 — Cliente baixa:
     • Clique "Baixar Laudo (PDF)"


5. TESTAR NOTIFICAÇÕES

   • Cada ação gera notificação para a outra parte
   • Veja badge contador no header
   • Acesse /notificacoes


6. TESTAR GALERIA

   • Upload múltiplas fotos em um registro
   • Clique em uma foto
   • Use setas ou teclado para navegar
   • ESC para fechar


7. TESTAR BACKUP

   • Na página do serviço
   • Seção "Backup"
   • Baixe TXT ou JSON


8. TESTES E2E

   cd tests
   npm run test:ui

❓ RETENÇÃO EM SERVIÇOS LONGOS

   Atualmente: 7 dias corridos a partir da criação do serviço.

   Problema: serviço que dure mais de 7 dias seria apagado ainda em andamento.

   Opções:
     A) Contar 7 dias a partir da CONCLUSÃO
     B) Permitir extensão manual (cliente/trabalhador solicita +7 dias)
     C) Pausar contagem enquanto EM ANDAMENTO
     D) Manter atual (serviços devem ser rápidos)

   Implementação atual: campo `expires_at` já existe, função cleanup já
   implementada. Fácil de mudar a regra.
